# Chase The Train：后端可行性验证

日期：2026-11-17。范围：中国铁路迷优先，兼顾未来扩展到其他地区。此文评估数据来源和后端实现可行性，尚未验证运营方数据授权。

## 结论

以铁路资料、个人乘车/拍车记录、收藏与社区为核心的产品可以实现。全国实时列车位置、余票和自动更新的完整时刻表不能作为首版承诺；它们依赖运营方授权或逐地区许可的数据源。

| 能力 | 可行性 | 首版处理 |
| --- | --- | --- |
| 账号、收藏、乘车记录、拍车记录、图片 | 高：自有业务数据和常规 CRUD | 实现；记录默认私密，发布由用户主动操作 |
| 车站、线路、车型资料检索 | 高：需要合法的种子数据和维护流程 | 先做可审核的资料库与编辑建议 |
| 地图展示、车站位置 | 技术可行；中国境内公开地图有资质、审图、数据部署要求 | UI 留接口；上线前确定合规地图服务商与数据授权 |
| 静态时刻表 | 有 GTFS 等标准，但覆盖和授权因地区而异 | 建数据适配层；只接入已核实许可的数据源 |
| 实时运行位置、晚点、车次动态 | 取决于授权实时 feed | 后续能力；绝不把估算位置标成实时位置 |
| 12306 余票、购票 | 当前没有确认可供本项目使用的官方开发者授权 | 不接入、不抓取、不收集 12306 凭据 |

## 已核查的依据

- [GTFS Schedule 规范](https://gtfs.org/documentation/schedule/reference/)定义站点、线路、行程、到发时刻等数据结构；[GTFS Realtime 说明](https://gtfs.org/getting-started/create/)支持行程更新、告警和车辆位置。标准存在不代表中国铁路数据源已开放。
- [Transitland API 文档](https://www.transit.land/documentation/rest-api)说明其检索 API 需密钥；能否使用具体 feed 仍需逐条核对覆盖、更新和授权。
- [OpenStreetMap 许可](https://www.openstreetmap.org/copyright/en)要求署名并受 ODbL 约束。[公共 Overpass 服务说明](https://wiki.openstreetmap.org/wiki/Overpass_API)提示共享实例不适合作为有保障的生产查询依赖。[Nominatim 使用政策](https://operations.osmfoundation.org/policies/nominatim/)限制公开实例流量与自动补全用途。
- [12306 服务条款](https://kyfw.12306.cn/otn/regist/rule)第 6 条限制未经认可的机器人、爬虫访问，第 12 条限制内容复制与再分发。研究未找到对本项目公开授权的开发者 API；这只是目前核查结果，并非证明不存在合作渠道。
- [《地图管理条例》](https://xzfg.moj.gov.cn/front/law/detail?LawID=421&Query=)对中国境内公开地图及互联网地图服务的资质、审核、地图数据库和服务器位置作出要求。地图功能发布前需确认具体业务方式与服务商满足适用规定。

## 实际探测

对公共 Overpass 实例进行了一次北京站附近铁路车站的小范围只读查询；本机在 12 秒内未取得响应。该结果不能判断数据覆盖，但说明首版后端不应在用户请求路径直接依赖此公共实例。资料导入应采用有许可的数据包或稳定的服务商接口，并有本地缓存、限流、来源与更新时间字段。

## 推荐后端方案

Next.js 负责页面和轻量 BFF；业务 API 可先通过 Next.js Route Handlers 形成模块化单体，避免过早拆服务。PostgreSQL 存账号、资料和日志；涉及空间查询时使用 PostGIS。图片存兼容 S3 的对象存储，上传由服务端签发短期凭证。异步任务处理缩略图、EXIF 清理、审核及数据导入。公共 API 使用版本号、游标分页、限流和来源标记。

数据源适配器必须输出 `source`、`license`、`retrieved_at`、`valid_until`、`confidence`；没有授权或已过期的数据不得作为实时信息展示。中国境内地图上线与公开用户位置标注作为独立发布门槛。

## 下一道验证门槛

1. 确定首发地区、运营主体与部署位置。
2. 取得车站/线路/车型种子数据的来源和许可清单，并抽样检查准确度。
3. 选定中国境内可用的合规地图服务商，确认公开标注与地图数据处理方式。
4. 如果加入时刻表，先签定或确认具体数据源授权，再做导入验证。
